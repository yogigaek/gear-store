# API edge-case matrix

Which test covers each kind of edge case, per critical module. Names are the `it(...)` titles; the file is
given once per table. `n/a` says why a category does not apply. Coverage of these tests is enforced by
`npm run test:cov -w @gear-store/api` (unit and e2e specs together, ≥ 90 % lines and branches).

Shared by every module: database errors become plain replies (P2002 → 409, P2025 → 404, others → bare 500) in
`errors.e2e-spec.ts`; bodies over 32 KB are refused with 413 in `app.e2e-spec.ts`; unknown JSON fields are
stripped by the zod pipe (tested per module below as "ignores …").

## Not covered on purpose

The combined run leaves about 31 of 747 branches uncovered (see `npm run test:cov`):

- About 13 are TypeScript decorator metadata (`typeof X === 'undefined' ? Object : X` on each `@Injectable()`
  class line); no test can reach the `Object` side.
- Defensive branches for states the code above them rules out: `CartService.resolve` cutting lines past 50
  (the input schema already caps lines at 50); `?? 0` / `?? []` fallbacks on values the query filters to
  non-null (`OrdersRepository`, `AdminStatsService`, `BuildService`); "Order not found" right after the order
  was created; `CurrentAuth` without its guard (every route using it is guarded); the refresh token row
  vanishing between its lookup and the session lock (needs a second connection paused inside the transaction).
